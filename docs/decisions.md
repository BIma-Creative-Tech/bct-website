# Catatan Keputusan (ADR mini)

Format: tanggal — keputusan — alasan — alternatif yang ditolak. Maksimal ±5 baris per entri. Dijaga oleh agent docs-keeper.

- **2026-08-24 — Multi-agent dengan lead orchestrator.** Semua pekerjaan multi-langkah lewat agent `lead` yang mendelegasikan ke spesialis dan menjaga checklist. Alasan: owner solo 5–10 jam/minggu butuh proses yang konsisten tanpa mengandalkan ingatan. Ditolak: bekerja ad-hoc tanpa pembagian peran.
- **2026-08-24 — Status ✅ hanya dari konfirmasi owner.** Agent maksimal menaikkan status ke 🟨 KONFIRMASI-OWNER. Alasan: owner adalah quality gate terakhir dan harus tahu persis apa yang berubah. Ditolak: auto-done oleh QA.
- **2026-08-24 — Governance check di CI.** Perubahan kode tanpa update CHANGELOG + checklist = CI merah. Alasan: dokumentasi & monitoring harus otomatis tertagih, bukan mengandalkan disiplin. Ditolak: konvensi tanpa penegakan.
- **2026-08-24 — Deploy utama Vercel, Docker sebagai jalur self-host/rilis versi.** Image GHCR dibuat per tag rilis untuk versioning yang bisa diaudit. Ditolak: full VPS-only (maintenance lebih berat untuk situs marketing).
- **2026-08-24 — Dependency zod ditambahkan.** Untuk validasi input API lead. Justifikasi: standar industri, dipakai juga di nextjs-odoo.
- **2026-08-24 — Copy dipisah dari data.** Teks halaman tinggal di `content/copy/*` sebagai objek bertipe; `content/site.ts` tetap satu-satunya sumber harga, nama paket, dan kontak. Alasan: mencegah angka harga terduplikasi di banyak file dan basi diam-diam. Ditolak: menaruh copy langsung di dalam komponen.
- **2026-08-24 — Domain sementara `http://localhost:3000`.** Berlaku sampai W3-04 (deploy + domain) selesai. Konsekuensi: `metadataBase`, canonical, dan URL OG menunjuk localhost — blocker deploy production yang dicatat sebagai komentar di `content/site.ts`. Ditolak: mengarang domain produksi sebelum dikonfirmasi owner.
- **2026-08-24 — ESLint flat config tanpa `FlatCompat`.** `eslint-config-next` v16 sudah mengekspor flat config di subpath `./core-web-vitals` dan `./typescript`, jadi `@eslint/eslintrc` tidak diperlukan. Alasan: nol dependency baru. Ditolak: menambah dependency demi kompatibilitas config legacy.
- **2026-08-24 — `react/jsx-no-target-blank` dikeraskan ke `error`.** Preset Next mematikan rule ini, padahal situs penuh tautan `wa.me` dengan `target="_blank"` yang tanpa `rel="noopener noreferrer"` membuka celah reverse tabnabbing. Ditolak: mengandalkan perilaku default browser modern saja.
- **2026-08-24 — Email tidak pernah dirender sebagai teks atau `mailto:` di HTML.** Alamat resmi BCT saat ini adalah alamat pribadi owner, jadi hanya disimpan sebagai data di `content/site.ts`. Kontak diarahkan ke WhatsApp dan form `/api/lead`. Ditolak: menampilkan `mailto:` di footer/halaman kontak (panen bot spam).
- **2026-08-24 — Pengukuran Lighthouse dipindah dari DoD W1-03 ke W3-01/W3-03.** Alasan: skor butuh build ter-deploy plus aset SEO/OG yang baru dikerjakan di W3. Scope item W1-03 dikecilkan, standar kualitasnya tidak diturunkan. Ditolak: meloloskan W1-03 dengan klaim Lighthouse yang tidak pernah diukur.
- **2026-08-24 — Judul halaman disusun eksplisit di segmen root.** `title.template` Next tidak berlaku untuk `app/page.tsx` karena berada di segmen yang sama dengan layout-nya, jadi sufiks `— Bima Creative Tech` ditulis eksplisit (`title.absolute`). Alasan: pola judul di CLAUDE.md tetap dipenuhi. Ditolak: mengandalkan template dan membiarkan judul beranda tanpa merek.
- **2026-08-24 — Rute produk literal, bukan `/produk/[slug]`.** Tiga `page.tsx` tipis (≤ 18 baris) yang mendelegasikan seluruh struktur ke `<HalamanProduk>` di `components/sections/`. Alasan: tiap produk bisa diberi perlakuan khusus kelak tanpa membongkar rute, sementara duplikasi tetap nol karena strukturnya bersama. Ditolak: rute dinamis `[slug]` (lebih ringkas tapi mengunci ketiga produk pada satu bentuk halaman), dan tiga halaman copy-paste (duplikasi struktur).
- **2026-08-24 — `og:title` ditulis eksplisit dengan sufiks merek, `title` tidak.** Terverifikasi di Next 16.3.2: `title.template` dari root layout berlaku untuk `<title>` di segmen anak, tapi **tidak** untuk `og:title` — di `node_modules/next/dist/lib/metadata/resolve-metadata.js` template Open Graph diambil dari `openGraph.title.template` milik segmen induk, dan `app/layout.tsx` tidak mendefinisikan `openGraph` sama sekali sehingga templatenya `null`. Konsekuensi: `title` ditulis tanpa sufiks, `og:title` dengan sufiks eksplisit; wajib ditinjau ulang bila `openGraph` kelak ditambahkan ke root layout. Ditolak: mengasumsikan template berlaku untuk keduanya (menghasilkan sufiks dobel).
- **2026-08-24 — Pengecualian baseline keamanan: `'unsafe-eval'` dev-only (G-14).** Pelonggaran CSP pertama sejak `SECURITY.md` ditulis, jadi wajib tercatat. Batasnya dev-only dan fail-closed (`NODE_ENV === "development"` persis), nilainya dibakar saat build bukan runtime sehingga artefak deploy tidak boleh pernah dibangun dengan `NODE_ENV=development` atau `next build --debug-prerender`; verdict security-auditor LULUS dengan header produksi terbukti identik. Wajib ditinjau ulang saat naik versi Next. Ditolak: melonggarkan `script-src` untuk semua environment, dan membiarkan dev overlay pincang.
- **2026-08-24 — `app/not-found.tsx` dikerjakan sebagai W2-09, terpisah dari W2-01.** Alasan: 5 dari 9 rute sitemap masih 404 sampai W2-02..W2-06 selesai, dan 404 bawaan Next membocorkan `<title>` berbahasa Inggris di atas layout Indonesia. Temuan teknis: dokumentasi Next 16 hanya menyebut ekspor `metadata` untuk `global-not-found.js`, **tetapi uji empiris membuktikan `metadata` bekerja penuh di `not-found.js` tanpa menyalakan `experimental.globalNotFound`** — perilaku ini tidak terdokumentasi, jadi wajib diperiksa ulang saat upgrade Next. Ditolak: menyalakan flag eksperimental (perubahan `next.config.ts` = gerbang owner), dan menunda 404 ke W3-01.
- **2026-08-25 — Blok unduh rate card PDF tidak dirender di W2-02.** Keputusan owner: berkas `public/rate-card-bct.pdf` belum ada, dan tombol unduh yang menunjuk berkas kosong lebih merugikan daripada tidak ada tombol sama sekali. Copy dan tipe `rateCardPdf` di `content/copy/pricing.ts` dipertahankan utuh; penyambungannya dilacak sebagai W2-11 dan masuk Definition of Done rilis ("rate card PDF bisa diunduh"). Ditolak: generate PDF otomatis dari `content/site.ts` — menambah dependensi + maintenance, sementara kapasitas dev owner hanya 5–10 jam/minggu.
- **2026-08-25 — CTA sekunder halaman dialihkan sementara ke rute hidup, bukan dibiarkan menunjuk 404.** Keputusan owner untuk `/pricing`: hero `/tentang` → `/`, penutup `/studi-kasus` → `/produk/odoo`. Alasan: konsisten dengan aturan W2-09 bahwa di dalam `<main>` hanya ada rute hidup. Ditolak: membiarkan href asli dan mengandalkan 404 bermerek sebagai jaring pengaman. Konsekuensi: utang yang wajib ditagih balik saat W2-03 dan W2-04 ditutup, ditandai komentar `SEMENTARA (W2-02)` di kode.
- **2026-08-25 — `metadataProduk` digeneralisasi jadi `metadataHalaman(meta, path)`.** Alasan: mencegah blok metadata yang sama disalin empat kali di W2-03..W2-05, dan mengunci aturan sufiks judul vs `og:title` (ADR 2026-08-24) di satu tempat. `metadataProduk` tetap ada sebagai pembungkus tipis agar halaman produk tidak bisa salah mengirim copy halaman lain. Ditolak: menyalin blok metadata di tiap halaman.
- **2026-08-25 — Tautan menuju rute mati ditahan, section-nya tetap diisi konten lain.** Diterapkan di `/tentang`: section rekam jejak diisi angka `bukti[]` dari `content/site.ts` alih-alih merender `rekamJejak.tautan` ke `/studi-kasus` yang masih 404. Alasan: konsisten dengan aturan W2-09/W2-02 bahwa di dalam `<main>` hanya ada rute hidup, tanpa membuat section berubah jadi judul kosong. Ditolak: merender tautan ke 404, dan menghapus section-nya. Konsekuensi: copy tidak diubah sama sekali dan tautan tinggal dinyalakan saat W2-03 selesai.
- **2026-08-25 — G-05 diturunkan dari 🟨 ke 🔨 setelah uji nyata.** Alasan: status 🟨 sebelumnya bersandar pada catatan "perlu uji nyata saat form dibuat di W2" yang tidak pernah dilakukan; ketika akhirnya dilakukan, tiga dari lima pilar baseline `SECURITY.md` terbukti tidak berfungsi seperti yang tertulis di komentar kode. Ditolak: membiarkan G-05 di 🟨 dan menyerahkan penilaiannya ke owner tanpa bukti, serta membangun form W2-05 lebih dulu di atas endpoint yang belum benar.
- **2026-08-25 — `/api/lead` membalas 503 saat `LEAD_WEBHOOK_URL` kosong, bukan `{ok:true}`.** Alasan: situs tidak boleh memberi tahu pengunjung "Pesan Anda terkirim" ketika tidak ada yang menerimanya; kehilangan lead senyap adalah kegagalan termahal untuk bisnis dengan kapasitas 5–10 jam/minggu. Konsekuensi yang disengaja: sampai owner mengisi env, form kontak menampilkan error jujur alih-alih sukses palsu. Ditolak: membalas 200 dan menganggap webhook opsional.
- **2026-08-25 — Header penerus hanya dipercaya bila `VERCEL === "1"`.** Alasan: memercayai `x-forwarded-for` yang ditulis klien membuat penyerang memilih ember rate limit-nya sendiri — terbukti 20.000 request dengan IP palsu unik lolos tanpa satu pun ditolak. Konsekuensi: di deploy tanpa proxy tepercaya, identitas tidak dipakai dan semua trafik berbagi ember global — fail-closed yang disengaja. Ditolak: env `TRUST_PROXY_HEADERS` baru (butuh dokumentasi `.env.example` dan keputusan owner), dan tetap memercayai header apa adanya.
- **2026-08-25 — Awalan aman spreadsheet diterapkan per baris, tanpa pengecualian untuk `- ` (dash-spasi).** Alasan: parser formula Excel mengabaikan spasi antara operator dan operan, jadi `- cmd|...` sama berbahayanya dengan `-cmd|...`; pengecualian demi kerapian daftar akan membuka kembali lubangnya. Konsekuensi: pada sink Sheets `USER_ENTERED` kutipnya diserap dan tidak tampil, jadi noise-nya justru jatuh pada sink yang memang tidak mengeksekusi formula. Ditolak: escape hanya karakter pertama string, dan heuristik pengecualian daftar.
- **2026-08-25 — Konstanta batas isian tinggal di `app/api/lead/batas.ts`, bukan di-re-export dari `route.ts`.** Alasan: mengimpor dari route menyeret zod + `NextResponse` (~373 KB) ke bundel klien hanya untuk membaca tiga angka; re-export akan menyisakan jalur impor berbahaya itu sambil menunjuk pembaca ke sana. Terverifikasi auditor: nol `ZodError`/`NextResponse` di `.next/static/`. Ditolak: mengekspor konstanta dari `route.ts`, dan membiarkan form mengetik ulang angkanya.
- **2026-08-25 — Kartu jalur email tidak dirender di `/kontak` sampai BCT punya alias publik.** Alasan: ADR 2026-08-24 melarang alamat pribadi owner terbit ke HTML, dan kartu tanpa alamat maupun tombol hanya jadi jalan buntu bagi pengunjung. Konsekuensi: entri email di `content/copy/kontak.ts` dipertahankan utuh sehingga tinggal dinyalakan. Ditolak: merender alamat pribadi, dan menghapus entrinya dari copy.
- **2026-08-25 — Tombol submit form kontak inert sampai terhidrasi, memakai `useSyncExternalStore`.** Alasan: form tanpa `action` yang tombolnya aktif pra-hidrasi membocorkan nama, kontak, dan isi pesan ke query string sekaligus menghilangkan lead (blocker [TINGGI] W2-07); pola `useState` + `useEffect` ditolak lint proyek (`react-hooks/set-state-in-effect` = error). Ditolak: `useState`+`useEffect`, dan menambahkan `method="post"` sebagai lapis kedua (pengiriman yang lolos akan mendarat di 405 — jalan buntu bagi pengunjung). **DIGANTIKAN SEBAGIAN 2026-08-26:** bagian “Ditolak: menambahkan `method="post"`” dicabut — lihat entri 2026-08-26 tentang `action="/api/lead"` di bawah. Sisa keputusan (tombol inert lewat `useSyncExternalStore`) tetap berlaku.
- **2026-08-25 — Komponen yang menyentuh `content/site.ts` dirender di server lalu dioper sebagai prop `ReactNode`, bukan diimpor client component.** Alasan: mengimpor `WaButton` ke client component menyeret seluruh `content/site.ts` — termasuk email pribadi owner — ke bundel setiap rute, membatalkan maksud ADR 2026-08-24 lewat pintu belakang. Dasarnya perilaku resmi Next (`node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md:178`): Server Component yang dioper sebagai `children`/prop tidak masuk graf modul milik Client Component. Ditolak: menambahkan `"use client"` ke `wa-button.tsx` (justru memperluas graf klien), dan mengoper `hrefWa: string` lalu merakit `<a>` sendiri di form (menyalin ulang `target="_blank"` + `rel="noopener noreferrer"` yang wajib karena `react/jsx-no-target-blank` dinaikkan ke error, sehingga jadi salinan kedua yang bisa melenceng).
- **2026-08-25 — Barrel `components/sections/index.ts` hanya boleh memuat komponen server.** Alasan: satu komponen ber-client di barrel membuat setiap halaman yang mengimpor barrel ikut mengapalkan chunk klien itu — terukur 6.770 B ke enam rute yang tidak punya form. Konsekuensi: komponen yang ber-`"use client"` atau yang mengimpor komponen ber-`"use client"` diimpor langsung dari berkasnya, seperti `HalamanKontak` di `app/kontak/page.tsx`. Ditolak: membiarkan `HalamanKontak` di barrel demi konsistensi impor.
- **2026-08-25 — `maxLength` tidak dipakai pada isian yang punya pesan `terlaluPanjang`.** Alasan: pemotongan senyap membuat pesan itu mustahil tampil, dan menghilangkan teks pengunjung tanpa pemberitahuan; batas atas tetap ditegakkan di pemeriksaan klien dan zod (422). Ditolak: menambahkan `maxLength` ke `pesan` demi konsistensi ke arah sebaliknya.
- **2026-08-26 — `method="post" action="/api/lead"` DIPAKAI di form kontak; membalikkan penolakan pada ADR 2026-08-25 (G-21a).** Alasan pembalikan: sejak G-20 mewajibkan `content-type: application/json`, submit `<form>` bawaan tidak pernah bisa mendarat di 405 — ia dijamin **415**, dan isiannya berpindah ke body POST, tidak pernah ke query string. `form.submit()` menurut spesifikasi tidak memicu event `submit`, jadi listener capture mustahil mencegatnya dan `action` adalah satu-satunya lapis yang menahan pengiriman pra-hidrasi. Terukur qa-reviewer dengan penanda rahasia di ketiga isian: **6 skenario submit paksa → 0 query param dan 0 lead pada 6/6**, POST `x-www-form-urlencoded` dan `multipart/form-data` → **415**, dan dengan JavaScript dimatikan penuh Enter maupun klik tidak memindahkan halaman. Ditolak: mengandalkan listener capture saja, dan membiarkan `<form>` tanpa `action`.
- **2026-08-26 — `content/rute.ts` adalah satu-satunya sumber kebenaran rute hidup (W2-12).** `RUTE_HIDUP` + `ruteHidup()`/`saringTautan()`/`tautanHidup()` dipakai tujuh komponen DAN `app/sitemap.ts`, jadi tidak ada daftar rute kedua di repo — `sitemap.xml` terbit dengan 7 `<loc>` dari daftar yang sama. Alasan: aturan “hanya rute hidup” sebelumnya ditegakkan tambal per berkas dan tetap bocor (2 error konsol 404 prefetch di setiap halaman). Terukur: menambahkan `"/studi-kasus"` — satu baris, satu berkas — mengembalikan tautannya di 8/8 rute + 1 entri sitemap tanpa menyentuh komponen mana pun. Modulnya sengaja bebas React dan bebas teks karena dipakai komponen server maupun client. Ditolak: menambal per-berkas (`HREF_DITUNDA` dicabut, 0 kemunculan tersisa) dan menulis daftar rute kedua di `app/sitemap.ts`. Batas yang diketahui: aturan ini belum dipaksakan mesin — tautan literal ke rute mati masih lolos lint/tsc/build/governance (dilacak G-23).
- **2026-08-26 — `content/site.ts` menjadi sumber TIPE slug produk, bukan hanya sumber data (W2-10 butir b).** `produk` kini `as const satisfies readonly Produk[]` dengan `export type SlugProduk = (typeof produk)[number]["slug"]`; `ProdukCopy["slug"]` dan `ItemNavProduk["slug"]` mengimpor tipe itu alih-alih menulis ulang union. Alasan: union tulis tangan membuat “jaring pengaman compiler” yang diklaim di catatan lama TIDAK ADA — produk keempat tanpa copy lolos `tsc`/`build` **exit 0** dan ikut terender ke 12 berkas; sesudah perbaikan skenario yang sama memberi **tsc exit 2 / build exit 1** dengan TS2741 yang menunjuk copy yang hilang. Konsekuensi `readonly` merembet dan ditangani backward-compatible (`DaftarPaket.paket` dan `DaftarTanda.item` dilebarkan, `app/page.tsx` dianotasi); nol perubahan nilai data. Ditolak: menulis ulang alasan `produkCopy` secara jujur tanpa memperbaiki apa pun, dan menghapus `produkCopy`. Batas: yang dipaksa ada adalah COPY, bukan RUTE (G-23).
- **2026-08-26 — Font kartu OG disimpan sebagai TTF di `assets/fonts/`, bukan di `public/` dan bukan diunduh saat build (W3-01).** Alasan: `ImageResponse` merender lewat satori, dan satori tidak bisa membaca `.woff2` keluaran `next/font/google` (nol dekompresor brotli di bundel `@vercel/og`); tanpa berkas ini kartu OG jatuh ke font bawaan Geist dan melanggar design system. `assets/` dipilih karena berkasnya hanya dibaca saat build dan tidak boleh dilayani ke pengunjung; file tracing Next tetap menyalinnya ke `.next/standalone/assets/fonts/` sehingga image Docker tidak kehilangan font. Ketiganya SIL OFL 1.1, jadi `LICENSE.txt` verbatim ikut didistribusikan. Ditolak: mengunduh font saat build (membuat setiap `next build` — termasuk stage Docker dan job CI — bergantung respons jaringan tak ter-cache demi aset yang isinya tidak pernah berubah), dan menaruhnya di `public/`.
- **2026-08-26 — Jendela kalibrasi honeypot: selama cincin belum punya `CONTOH_MINIMAL` pengukuran nyata, kiriman jebakan diperlakukan PERSIS seperti kiriman sah dan ikut diteruskan ke webhook (G-19).** Alasan: waktunya jadi identik karena memang kode yang sama, dan panggilan itu sekaligus mengisi cincin; benih konstan (`DURASI_WEBHOOK_AWAL_MS = 220`) terbukti memisahkan jebakan 100% ke dua arah. Harganya ditulis terang di kode: paling banyak `MAKS_KALIBRASI_JEBAKAN` kiriman spam mendarat di sink owner seumur proses. Ditolak, dikutip dari `app/api/lead/route.ts`: “(1) Tebakan konstan … menggantinya dengan konstanta lain hanya memindahkan arah bocor”; “(2) Menyamakan lantai … hampir setiap lead asli membayar 5 detik. DITOLAK: prinsip yang mengikat seluruh berkas ini … menyusahkan satu pengunjung sah lebih mahal daripada meloloskan satu spam.” Muatan PENANDA tanpa data pengunjung (yang akan menghapus sisa spam itu) = gerbang konfirmasi owner, sengaja tidak dikerjakan. **JANGAN DIBACA SEBAGAI JAMINAN:** security-auditor kemudian membuktikan pagar kuotanya TIDAK tertegakkan — `perluKalibrasi()` mengembalikan `true` sebelum sempat memeriksa `MAKS_KALIBRASI_JEBAKAN` selama cincin belum terkalibrasi (`app/api/lead/route.ts:634-638`), sementara cincin hanya terisi dari kiriman sah yang SUKSES. G-19 karena itu masih 🔨, bukan lulus.
- **2026-08-26 — Invariant yang selama ini hanya dijaga ingatan dikunci lewat guard build.** Dua skrip berpola sama dengan `scripts/check-governance.mjs`: `check-csp.mjs` (G-15 — `'unsafe-eval'` tidak boleh masuk artefak produksi) dan `check-pii.mjs` (G-22 — email/lokasi owner tidak boleh muncul di `.next/static/`, nilainya dibaca runtime dari `content/site.ts` supaya alamatnya tidak pernah ditulis literal di repo publik). Alasan: keduanya terbukti bisa dilanggar tanpa satu pun uji yang menangkapnya — `next build --debug-prerender` menghasilkan artefak ber-`unsafe-eval` dengan exit 0, dan satu pembacaan `site.email` dari client component cukup membuka lagi kebocoran G-18 (yang hari ini hanya tertahan dead-code elimination Turbopack). **Status: kedua skrip ada di branch `ci/guards` (PR #1) dan BELUM di-merge ke `main`** — step CI = gerbang konfirmasi owner; di `main` direktori `scripts/` hanya berisi `check-governance.mjs`. Ditolak: mengandalkan audit manual per rilis, dan menuliskan alamat email literal di dalam skrip.
