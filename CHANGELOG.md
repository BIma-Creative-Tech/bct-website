### Security

- G-13: `react/jsx-no-target-blank` dikeraskan ke `error` (preset Next mematikannya) — seluruh tautan `wa.me` bertarget `_blank` wajib membawa `rel="noopener noreferrer"` agar tidak bisa di-reverse-tabnab.
- W1-02: alamat email owner tidak pernah dirender sebagai teks maupun `mailto:` di HTML; jalur kontak diarahkan ke WhatsApp dan form `/api/lead`.
- G-14: `'unsafe-eval'` ditambahkan ke `script-src` di `next.config.ts` **hanya** bila `process.env.NODE_ENV === "development"`, agar React error overlay dan Fast Refresh (yang menyusun ulang callstack lewat `eval()`) berfungsi saat debugging. Header produksi tidak berubah sama sekali: security-auditor memverifikasi SHA-256 seluruh array header identik pada varian `NEXT_PUBLIC_UMAMI_SRC` kosong maupun terisi, dan cabangnya fail-closed terhadap 7 nilai `NODE_ENV` non-`development` (tidak diset, kosong, `production`, `test`, `staging`, `Development`, `DEVELOPMENT`). Verdict security-auditor: LULUS. Catatan operasional: nilai CSP dibakar saat BUILD, jadi artefak yang akan di-deploy tidak boleh pernah dibangun dengan `NODE_ENV=development` atau flag `next build --debug-prerender` (auditor membuktikan flag itu menghasilkan build exit 0 dengan `'unsafe-eval'` ikut terbakar). Guard CI untuk mengunci invariant ini sudah diantrekan sebagai item G-15 (menunggu konfirmasi owner karena menyentuh CI).

- G-05: `/api/lead` dikeraskan — lima blocker keamanan diperbaiki plus dua pengerasan, seluruhnya di `app/api/lead/route.ts` (78 → 390 baris), **nol dependensi baru**. Alur item ini: audit pertama (27 skenario terhadap build produksi) memvonis **TIDAK LULUS untuk dipakai form publik** dan menurunkan status G-05 dari 🟨 ke 🔨 → perbaikan di bawah → audit ulang oleh `security-auditor` (2026-08-25) dengan rangkaian uji yang sama persis sebelum dan sesudah → verdict **LULUS untuk dipakai form publik W2-05**. Angka "sebelum" di bawah adalah hasil audit pertama; blok ini menggantikan entri temuan versi lama agar tidak ada dua catatan G-05 yang saling bertentangan.
  - **Kunci rate limit tidak lagi ditulis klien.** `x-forwarded-for[0]` dibuang total; header penerus hanya dipercaya bila `process.env.VERCEL === "1"`, dengan urutan `x-vercel-forwarded-for` → `x-real-ip` → `x-forwarded-for`, dan untuk header berdaftar diambil elemen **paling kanan** (hop tepercaya terdekat) — bukan paling kiri. Tanpa hop tepercaya, header sengaja tidak dipakai sama sekali. Ditambah `normalisasiIp()` (buang port, IPv6 dikelompokkan per /64), ember global 30/menit untuk identitas tak dikenal supaya satu kantor di belakang NAT tidak mengunci form, dan pagar memori `MAKS_ENTRI = 5000`. Terukur — banjir 20.000 request dengan IP palsu unik: sebelum **20.000 diterima / 0 ditolak**, sesudah **30 diterima / 19.970 ditolak**.
  - **Honeypot berhenti membocorkan dirinya.** Skema dilonggarkan dari `z.literal("")` ke `z.unknown()`, dan kiriman ber-honeypot kini dibalas **200 `{ok:true}` tanpa meneruskan apa pun** — blok "pura-pura sukses" yang sebelumnya KODE MATI kini benar-benar hidup. Ceknya ditaruh setelah validasi zod DAN setelah cek `LEAD_WEBHOOK_URL`, supaya bot tidak bisa menemukan jebakan dengan membandingkan 422-vs-200 atau 503-vs-200. Terukur — honeypot terisi: sebelum **422** (membocorkan field jebakan), sesudah **200** dan nol yang sampai listener.
  - **Sukses palsu dihentikan.** `LEAD_WEBHOOK_URL` kosong → **503** (sebelum: **200 `{ok:true}`**, lead hilang senyap sementara `content/copy/kontak.ts` menjanjikan "Pesan Anda terkirim"); webhook membalas non-2xx → **502** (sebelum: **200** meski webhook balas 500); body balasan webhook di-`cancel()` agar koneksi tidak menggantung.
  - **Injeksi dinetralkan.** Karakter kontrol C0 **dan C1** (termasuk NEL U+0085), LS/PS (U+2028/2029), serta karakter bidi-override dan zero-width dibuang; `nama`/`kontak` dipaksa satu baris sementara `pesan` mempertahankan baris baru wajar. Awalan formula spreadsheet (`= + @ -`) diberi kutip aman **per baris** pada `pesan` — bukan hanya karakter pertama string — karena sink spreadsheet lazim memecah pesan per baris menjadi sel.
  - **Batas body & timeout.** Body ditolak **413** dari `content-length` >16 KB dan tetap dihitung ulang saat membaca stream (menutup chunked dan `content-length` bohong); fetch ke webhook memakai `AbortSignal.timeout(5000)`. Terukur — body 50 MB: sebelum **tertelan penuh**, sesudah **413 dalam 3 ms** (dan 5,5 ms untuk chunked tanpa `content-length`); webhook menggantung: sebelum **45 detik**, sesudah **abort 5,03 detik → 502**.
  - **Terverifikasi tidak turun** pada audit ulang: batas panjang zod di semua field + `.trim()`, enum `produk` cocok persis dengan `OpsiProduk`, nol PII dan nol URL webhook di log, respons error generik, non-POST → 405, dan tanpa header CORS.
  - **Syarat operasional** yang menyertai verdict LULUS (dilacak di `docs/checklist.md`, tidak diulang di sini): deploy wajib di belakang edge Vercel, `VERCEL=1` tidak boleh pernah diset manual di luar Vercel, dan rate limit lintas instans (state masih `Map` in-memory, jadi jatah berlaku per instance) menunggu keputusan owner sebagai item G-16.
